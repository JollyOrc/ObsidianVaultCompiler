# v0.12.0 Release Notes

**Download withdrawn (2026-10-30):** this build bundled the npm package
`text-mapper` (AGPL-3.0-or-later, CC-BY-SA-4.0), which the Unlicense of this
project cannot carry. Use v0.14.0 or later
([#89](https://github.com/JollyOrc/ObsidianVaultCompiler/issues/89)).

**Released:** 2026-10-27

Fixes a data-safety bug: an absolute output folder was written **into the
vault**. Adds writing to a folder outside the vault on the desktop app, and
puts every write of a compile behind one path check.

## Bug fixes

### An absolute output folder wrote into the vault (US-0.3, US-8.1)
With the output folder `/Users/user/Desktop` (chosen with `Browse`), v0.10.0
and v0.11.0 dropped the leading `/` and wrote
`<vault>/Users/user/Desktop/My Book.md`, its `assets/` and the
warnings file inside the vault. If you compiled to an absolute folder before,
look for such a folder in your vault and remove it yourself; the plugin does
not delete it.

### Browse took a sibling folder for a vault folder (AC-OL-3)
With the vault `/x/Vault`, picking `/x/Vault Backup/out` was stored as the
vault folder ` Backup/out`. A folder is now inside the vault only when the
vault root is followed by a path separator.

### Browse in the export prompt had no effect (AC-OL-7)
The prompt saved its old field text over the picked folder. The field now shows
the picked folder; the settings tab redraws after `Browse`.

## New features

### Output folder outside the vault (US-0.3 AC-OL-2, desktop app only)
An absolute folder outside the vault, such as `/Users/user/Desktop` or
`C:\Users\me\Desktop`, is written there with Node.js `fs`: the compiled file,
`assets/` and the warnings logfile. Nothing is created in the vault. The folder
must exist. On mobile such a folder is refused.

## Changed behaviour

These outputs are now refused before anything is read or written, with the
notice `Compilation not started: <reason>` (US-0.3 AC-OL-4 to AC-OL-6):

- a folder with `..` (`../Exports`) or starting with `~` (`~/Desktop`);
- a vault folder with `\` (`Exports\Sub`);
- a folder in the Obsidian config folder (`.obsidian/…`);
- a filename with `/` or `\`, an empty filename, `.` or `..`;
- an output path equal to the starting file (`index2compile.md`).

Every write of a compile (output file, warnings logfile, copied assets,
TextMapper PNGs, folders) goes through one output writer that refuses any path
outside the output location (US-8.1 AC-8.1-W). The "Resolved output path" in
the settings shows the reason when the current values are refused.

## Breaking changes

A filename that contains a folder (`sub/Book.md`) is refused; move the folder
part into the output folder field.
