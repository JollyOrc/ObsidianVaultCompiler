# v0.11.0 Release Notes

**Download withdrawn (2026-10-30):** this build bundled the npm package
`text-mapper` (AGPL-3.0-or-later, CC-BY-SA-4.0), which the Unlicense of this
project cannot carry. Use v0.14.0 or later
([#89](https://github.com/JollyOrc/ObsidianVaultCompiler/issues/89)).

**Released:** 2026-10-27

Implements the heading decisions of 2026-10-27 (OD-1 to OD-6) and fixes broken
links to embedded files (KD-1). **Compiled output changes** — see "Breaking
changes".

## Changed behaviour

### One title rule everywhere (US-6.4, US-6.1, US-2.3)
Every heading the compiler writes for a file, and every link label and anchor
that points at one, uses the same title: the filename without its numeric
prefix and extension, first letter upper-cased, everything else as written.
`2.2.2 Third-Level.md` → `Third-Level` (was `2.2.2 Third Level` with the toggle
off). Links now always find their heading: on the example vault, anchor links
without a matching heading dropped from 68 to 23 (toggle on) and from 146 to 22
(toggle off). The remaining ones are author-written links to headings inside
notes (KD-2, not yet decided).

### "Normalise headings" off now means US-6.1 (OD-4)
With the toggle off, the plugin passed `false`, which kept every heading as
written; US-6.1 filename headings never ran for users. They now do, with levels
up to h6.

### With "Normalise headings" on (US-6.3 to US-6.5)
- **OD-1:** the first heading of a heading-first file is replaced by the file's
  title (`1.2 Combat.md` starting `# Fighting` → `## Combat`).
- **OD-2:** every unprefixed embed — heading-first, preamble, pass-through or
  section — goes one level below the last original heading above it, else one
  below the embedding file. After `## Chapter` they all land at h3 (were h1,
  h3, h2 and h2).
- **OD-3:** section embeds move up as well as down (`## Body Magic` embedded from
  the root → `# Body Magic`).
- **OD-5:** clamped headings are reported in the warnings only (unchanged).
- **OD-6:** a pass-through wrapper shows its target at the wrapper's depth with
  the target's title (`A.md` = `![[B.md]]` → `# B`); a link to the wrapper
  points at that heading.

## Bug fixes

- KD-1: links to normalised files pointed at anchors that did not exist.
- The heading context of an embed is now taken from its own line. Before, an
  image or section embed earlier in the file shifted the context of every later
  embed, so a file could land at the wrong level.
- Warning line numbers for embeds come from the embed's own line in all cases.

## Breaking changes

Compiled documents look different: heading text from filenames no longer
carries the numeric prefix, hyphens are kept, authors' first headings are
replaced by the filename, and levels follow the new depth rule. Re-compile and
review the output; source notes are unchanged.
