# v0.13.0 Release Notes

**Download withdrawn (2026-10-30):** this build bundled the npm package
`text-mapper` (AGPL-3.0-or-later, CC-BY-SA-4.0), which the Unlicense of this
project cannot carry. Use v0.14.0 or later
([#89](https://github.com/JollyOrc/ObsidianVaultCompiler/issues/89)).

**Released:** 2026-10-27

YAML frontmatter no longer shows up in the compiled document.

## New features

### Frontmatter is removed from every note (US-5.2)
A note that starts with a `---` line and has a later closing `---` line has
that block removed when it is read, before any other rule runs. This applies to
the root file and to every embedded note, with "Normalise headings" on and off.
No frontmatter field, including `tags`, is carried into the output. That was the
user's decision of 2026-10-27, made after a tag line and an italic `Tags:` line
were tried on the example vault.

Before this release, a spell note `---` / `tags:` / `  - BodyMagic` / `---` /
`Spell text.` compiled to its title followed by the raw YAML and two `---`
rules. In the example vault, 93 such blocks reached the compiled rulebook.

## Changed behaviour

- A note with frontmatter followed by a heading is now heading-first: its first
  heading after the frontmatter is the one the title replaces (US-6.3 AC-6,
  US-6.1 AC-4). Before, the note counted as a preamble file and kept both.
- A wrapper whose only other content is frontmatter is now a pass-through
  (US-6.5).
- YAML comments (`# …`) and list items (`- [[Note]]`) in the frontmatter are no
  longer read as headings, section anchors or ToC entries.
- A `---` that is not frontmatter (in the middle of a note, or a first-line
  `---` with no closing line) is kept as a horizontal rule.

## Bug fixes

- Warnings raised for an embed give the line number in the source note. They
  now count the frontmatter lines, and with "Normalise headings" on they no
  longer count the injected title as a line (US-8.4, US-5.2 AC-12).

## Breaking changes

None. If you relied on frontmatter text showing up in the output, put it in
the note body instead.
