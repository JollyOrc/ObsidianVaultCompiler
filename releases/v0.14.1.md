# v0.14.1 Release Notes

**[⬇ Download obsidian-vault-compiler-v0.14.1.zip](obsidian-vault-compiler-v0.14.1.zip)**

**Released:** 2026-10-27

Fixes the two findings of manual check M14 on v0.14.0.

## Bug fixes

### Maps use the font Obsidian draws them in (US-4.8, T-4.8-B)
With "Map font" empty, v0.14.0 wrote Obsidian's font list into the map, but
none of its fonts is installed on the system (Inter exists only inside
Obsidian, Bookerly is not defined at all), so the PNG fell back to Times.
Now the compiler:
- embeds every font Obsidian defines for the names in the list (here Inter)
  into the map, so the PNG matches Obsidian;
- appends `sans-serif` to a list without a generic family, as a last resort;
- shows a notice if a font file cannot be read.
The same applies to a font typed into "Map font".

### A new font shows up in existing output folders (US-4.8 AC-6)
Map PNGs are now named `<map hash>_<font key>.png`. A second compile with a
different font creates new PNGs instead of reusing the old ones. Old PNGs stay
in the folder unused.

## Breaking changes
Map PNG names change from `<hash>_0001.png` to `<hash>_<font key>.png`.

## Manual check
M14 retest passed (2026-10-27): with "Map font" empty the PNG uses the same
sans-serif as Obsidian; a typed font creates new PNGs in the same folder.
