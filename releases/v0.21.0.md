# v0.21.0 Release Notes

**Released:** 2026-11-01

## New features

### Embed a note as a quote (US-1.5, #106)
An embed on a quote line now shows the whole note as one quotation:

```markdown
> ![[Sage sayings]]
```

becomes

```markdown
> **Sage sayings**
>
> # Sayings of the hedge sage
>
> Patience mends more than charms.
```

- The quote opens with the note's name in bold (`*` and `_` escaped); its
  headings stay exactly as written and are not part of the book's heading
  structure, with "Normalise headings" on and off.
- Works with both embed syntaxes, in nested quotes (`> > ![[…]]`, the prefix
  as written) and in callouts; quote lines before and after the embed stay in
  the same quote.
- A section embed (`> ![[Note#Section]]`) quotes the section without the bold
  name.
- Notes the quoted note embeds go into the same quote, each with its own bold
  name; a pass-through wrapper shows only its target's name.
- Lists of links inside a quoted note stay lists (no table-of-contents
  expansion).
- A note that appears only as a quote is not part of the book: links to it
  give the "not embedded in compiled output" warning. A note that is quoted
  and also listed in a table of contents is embedded from the list as before,
  and links to it go to that copy. Headings inside a quote are no link
  targets, as in Obsidian (checked in Obsidian's reading view).

Until now only the first line of the note (its generated heading) ended up in
the quote; the rest fell out of it and was renumbered.

## Bug fixes

### Code inside a quote is copied as written (US-1.4 AC-7, #105)
A `> ~~~` block was not seen as code: its links were converted and its embeds
pasted in, which broke the quote. A quoted ```` ``` ```` block was protected
only while its backtick runs happened to pair up. Fenced and indented code
inside quotes (and callouts) is now code; a quote that ends closes the code
block inside it.

## Breaking changes and migration
None expected. A book that relied on `> ![[Note]]` producing a heading plus
the note outside the quote should write `![[Note]]` without `> `.
