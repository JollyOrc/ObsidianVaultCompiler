# v0.22.0 Release Notes

## New features

### Entries: note properties as data for a statblock (US-9.1, #110, #111)
A note whose properties include one of the **Entry marker keys** (a new
setting, empty by default) is an *entry*. Its properties go into the
document as an `o2t-entry` block directly under its heading, for the
typesetting plugin Obsidian2Typst (0.12.0 or later), which prints them as a
statblock and shows the block as one in Obsidian:

````markdown
### Fen Hare
```o2t-entry
vigour: 11
might: 4
attacks:
  - "Kick: 2d6"
skills:
  - Quick Step
tags:
  - beast
illustration: "![Drawn by A. Nobody](assets/hare.png)"
```
Fen hares are quick and shy. …
````

- Every property is kept, `tags` included, except the **Entry exclude keys**
  (default `aliases, cssclasses, publish`); names in lower case, in the
  note's order; written in the form Obsidian's Properties panel writes.
- Links in values become their text; bold and italic stay.
- Only notes brought in whole get a block — not sections, quotes or the
  starting note. The block's format is specified by its reader
  (Obsidian2Typst, `docs/technical/entry-block.md`).

### Pictures named in properties (US-9.2, #112)
A picture in an **Entry image key** (default `illustration`) is copied into
`assets/` like an embedded picture, with its credit:
`[[hare.png|Drawn by A. Nobody]]` → `![Drawn by A. Nobody](assets/hare.png)`.
Every link form works; `[[picture.png|Credit]]` is the one Obsidian keeps up
to date when the picture moves. A size (`|300`) is never a credit. A list, a
web address, a note or a non-picture is reported and left out.

### Each entry once (US-9.3, #113)
An entry note that two lists bring in appears only the first time; the
second place holds `<!-- repeat of "Fen Hare" omitted -->` and the warnings
file lists *Duplicate entry omitted*. Other notes still appear as often as
they are listed.

### Notes that never made it into the book (US-9.4, #114)
A new setting, **Expect compiled folders**: every note in those folders that
isn't in the document as a whole note is listed in the warnings file (*Not
compiled*, or *… (section embed only)* / *… (quoted only)*). The message
after a compilation names the counts and the warnings file.

## Changed behaviour

### The output folder is never read (US-3.1, #109)
Files in the output folder are left out when links are resolved: they are
earlier results, not sources. A picture copied to `Exports/assets/` by an
earlier run no longer makes its name ambiguous or stands in for a deleted
original. Applies to the folder in the settings and to one typed for a run;
an empty output folder (the vault root) leaves nothing out.

### Obsidian-only blocks in every form (US-5.1 AC-F, #116)
Dataview, DataviewJS, Meta Bind, Leaflet, Calendarium and compressed-JSON
blocks are now removed when written with `~~~`, with four or more backticks,
or inside a quote (before, they stayed as code or left a stray line). The
language must be the exact word: a block marked e.g. `dataviewish` is now
kept (before, it was removed as a prefix match). A block without its closing
line is kept and reported, so a missing line never deletes the rest of a
note.

## Bundled package
`yaml` 2.9.1 (ISC licence) reads properties and writes the entry block; its
licence notice heads `main.js`. `main.js` grows from about 61 KB to 163 KB.

## Breaking changes and migration
None for books that don't set **Entry marker keys**. If you relied on a
`dataview…`-prefixed block language being removed, name it exactly. If a link
pointed into the output folder on purpose, point it at the source.
