# Release Notes — v0.5.0

**Released:** 2026-10-15

---

## Bug fixes

### Accented-character slugs no longer collapse to empty strings
`slugify` now applies Unicode NFD decomposition before stripping non-ASCII
characters, so a title like "Château Frontenac" produces a well-formed slug
(`chateau-frontenac`) instead of an empty string.  A final guard ensures the
slug never returns `""` — it falls back to `"_"` for inputs that become
entirely empty after normalization.  Fixes the `fuzz — slugify` test.

### Title-case now keeps small words lowercase
`titleFromFilename` no longer capitalises conjunctions, articles, and short
prepositions in the middle of a title.  "2.9 Treasure and Equipment" stays
exactly that, instead of becoming "2.9 Treasure And Equipment".  The full list
of protected words: _a, an, the, and, but, or, nor, for, at, by, in, of, on,
to, up, as, is, it_ (first-word capitalisation still applies unconditionally).

## New features

### T-8.4 — Provenance tracking for post-assembly warnings
`convertLinks` and `sanitizeOutput` previously attributed every warning they
produced to `file: 'compiled-output'`, which was unhelpful because users need
to know which vault file contains the offending link, not where it ended up in
the merged document.

Version 0.5.0 introduces inline provenance sentinels: each file's content
block is wrapped with `<!-- __vs__:path -->` / `<!-- __ve__:path -->` markers
during assembly.  Post-assembly passes use a stack simulation over these
markers to attribute each warning to the correct vault source file and
approximate line number within that file.  Sentinels are stripped before
`CompileResult.content` is returned, so they never appear in the output.

Acceptance: no `WarningDetail` entry in any `CompileResult` has
`file === 'compiled-output'` for warnings originating from wiki-link
conversion or output sanitization.

### US-8.3 — Warn when a wiki link target is not embedded in the compiled output
Previously, a `[[link]]` whose target file existed in the vault but was never
embedded (not reachable from the start file) was silently converted to a broken
anchor `[label](#slug-that-does-not-exist)`.

Now such links are replaced with:
```
<!-- Warning: link target 'X' not embedded in compiled output -->
```
and a corresponding `WarningDetail` entry with the correct source file and line.
The warning message is `link target 'X' not embedded in compiled output`.

## Developer tooling

- `txt-loader.mjs` doc-comment corrected: use `--loader ./txt-loader.mjs`
  (not `--import`). `--import` in Node 22 only pre-loads the module without
  registering ESM hooks; `--loader` (deprecated but functional) correctly
  installs the `.txt` hook.
- `package.json` now includes a `test` script:
  `node --loader ../txt-loader.mjs --experimental-strip-types --test ../tests/**/*.test.ts`

## Upgrade notes

No breaking API changes.  `CompileResult.warningDetails` entries that previously
carried `file: 'compiled-output'` for link-conversion warnings now carry the
originating vault file path.  Consumers that special-cased `'compiled-output'`
should remove that check.
