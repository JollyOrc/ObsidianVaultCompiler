# v0.7.0 Release Notes — Heading Normalisation (US-7.1)

## Summary

Heading normalisation automatically adjusts heading levels when embedding files, so each file's headings nest correctly within the overall document hierarchy. This removes the need to manually track heading depth across included files.

## Feature: `normaliseHeadings` option (US-7.1)

### How it works

When `normaliseHeadings: true` is set (compiler option) or the **Normalise headings** toggle is enabled in Obsidian settings:

1. **Prefixed files** — files with a numeric prefix like `1.3.2 Magic.md` are placed at the corresponding depth (h3). All headings in the file shift uniformly so the first heading lands at h3.
2. **Unprefixed files** — files without a numeric prefix inherit their depth from the embedding context: a file embedded at depth 1 has its first heading placed at h2, one embedded inside that at h3, and so on.
3. **Section embeds** (`file#anchor`) — the extracted section's shallowest heading is shifted to `embeddingDepth + 1`.
4. **No headings** — files with no headings are included as-is; no heading is injected.

### Clamping and warnings

- **Floor clamping**: if a prefixed file's absolute depth would place it shallower than its embedding context, the depth is clamped to `parentDepth + 1` and a `WarningDetail` is emitted.
- **Ceiling clamping**: headings that would exceed h6 after shifting are clamped to h6 and a warning is emitted.
