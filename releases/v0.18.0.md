# v0.18.0 Release Notes

**Released:** 2026-10-31

## Changed behaviour

### Images from the web stay in the document (US-2.6, #94, #96)
`![Logo](https://example.com/logo.png)` used to disappear from the compiled
document and was reported as a missing asset. It now stays exactly as written
and is shown from the web when the document is read; nothing is copied and
nothing is reported. `![[https://example.com/logo.png]]` becomes
`![](https://example.com/logo.png)`.

### A list of pictures stays a list (US-1.3 AC-2, #96)
A list item that embeds a picture or other file now keeps its bullet:
`- ![Front](front.png)` → `- ![Front](assets/front.png)`. Items that embed a
note still lose their bullet, so the note does not start on a list marker.
A wiki picture with a size in a list keeps it as well
(`- ![[pic.png|200]]` → `- ![200](assets/pic.png)`).

**Migration:** if a book relied on picture lists losing their bullets, write
the pictures without `- `.

## Bug fixes

### Image titles (US-2.6, #96)
`![Logo](logo.png "Company logo")` was reported as a missing asset although
the file exists. It is now copied, and the title is kept:
`![Logo](assets/logo.png "Company logo")`. Angle brackets around a path with
spaces work too.

### Warnings name the right line (US-8.4 AC-5, #95, #97)
Every warning now names the line as it is in the note, frontmatter included.
Before, the line was off after notes embedded above it, after a table of
contents, a map block or a Dataview block, below frontmatter, and with
"Normalise headings"; a link brought along by a section embed was reported in
the wrong note.
