# v0.27.0 Release Notes

**[⬇ Download obsidian-vault-compiler-v0.27.0.zip](obsidian-vault-compiler-v0.27.0.zip)**

**Released:** 2026-11-26

A starting note can say where its compile goes and which Obsidian2Typst preset
prints it, so a rulebook and an adventure's sheets each keep their own target.

## New features

### A compile target in the starting note (US-7.5, #137, #138, #139)
Two properties of the starting note:

```markdown
---
compile-folder: Sheets
compile-file: keep-sheets.md
---
```

set the output of a compile from that note — from the file menu, the compile
dialog and **Compile vault** alike. A property left out falls back to the
setting. The settings' output folder and file name are not changed by such a
compile. The dialog shows the note's values with `Output from the note's
properties`; editing them there applies to that compile only. The same path
rules as the settings apply; a refusal names the property.

### Compile target… (US-7.5, #139)
A new item in a note's file menu opens a small dialog (folder with
**Choose folder…**, file name, **Save**, **Clear**) that writes or removes the
two properties. Only these two properties change; the note's other properties
keep their exact text.

### The preset travels (US-7.5, #138)
When the starting note has `typst-preset`, the compiled file starts with that
one property; Obsidian2Typst 0.19.0 exports and previews the compiled note with
that preset.

## Changed behaviour

- A compile from a starting note without these properties writes the same
  output and saves the same settings as 0.26.0.
- US-8.1 amended: outside a compile, the plugin writes to a note only through
  **Compile target…**, on your action, and only its two properties.
