# Release Notes — v0.6.1

**Released:** 2026-10-15

---

## Bug fix: markdown-syntax anchor embeds now extract sections correctly

### What was wrong

`![alt](file.md#Heading)` (standard markdown embed syntax) ignored the
`#Heading` anchor and embedded the entire target file, even after v0.6.0
introduced section extraction for `![[file.md#Heading]]` (wiki syntax).

In the Example Vault vault this caused `1.3.2 Magic.md` to be
included in full eleven times: once as an intentional full embed, and once for
each of the eight `![Section](1.3.2 Magic.md#Section)` lines in
`1.4.3 Magic Skills.md` — plus additional full-file copies from `Chakra.md`
and `Spell Enhancements.md`.

### Root cause

The compiler has two code paths for embeds: `processWikiEmbeds` (handles
`![[…]]`) and `processMarkdownEmbeds` (handles `![…](…)`). Both call the
shared `resolve()` helper, which correctly parses the anchor from the path. In
v0.6.0, the anchor-handling block was added to `processWikiEmbeds` but
`processMarkdownEmbeds` was not updated — it still called
`processMarkdown(path, true)` unconditionally.

### Fix

`processMarkdownEmbeds` now contains the same anchor-handling block as
`processWikiEmbeds`: when `resolved.anchor !== null`, it calls
`processMarkdown(path, false)` (preserving the file's own headings) and then
passes the result to `extractSection()`.

---

## Global requirement added

A new resolved decision in the user stories formally states:

> **Both embed syntaxes are treated identically throughout the compiler.**
> Every embedding behaviour — recursive inclusion, heading-anchored section
> extraction, auto-heading injection, circular-dependency detection, and
> missing-reference warnings — applies equally to `![[file.md]]` (wiki syntax)
> and `![alt](file.md)` (standard markdown syntax). No behaviour may be
> implemented for one syntax without being implemented for the other.

US-1.2 was amended to reference both `![[file.md#Heading]]` and
`![alt](file.md#Heading)` in the heading-anchored embed criterion.

## Upgrade notes

No breaking API changes. Consumers using `![alt](file.md#Heading)` markdown
embeds will now receive section-only output instead of the full file; this
matches what `![[file.md#Heading]]` already produced.
