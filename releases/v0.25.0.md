# v0.25.0 Release Notes

**[⬇ Download obsidian-vault-compiler-v0.25.0.zip](obsidian-vault-compiler-v0.25.0.zip)**

**Released:** 2026-11-18

The plugin's screens follow the preferred UI standard for Obsidian plugins:
a compile window when you want to choose, a direct command when you don't,
settings in sections. The compiled book is unchanged.

## New features

### A compile window (US-7.4 AC-1 to AC-4, #127, #128, #130)
A ribbon icon and the command **Compile vault…** open a window titled
*Compile vault* with the starting file, the output folder (with **Choose
folder…**), the output filename and the **Compile** button. A grey line says
what will happen, made again as you type:

```text
Exports/compiledtext.md will be written.
Exports/compiledtext.md exists (from 2026-11-17 14:02) and will be replaced.
```

When the values are refused, a red line gives the reason and **Compile** is
disabled. Enter compiles (not while an input method composes); Escape, the ×
and a click outside close the window and save nothing. **More options** (the
gear) opens the plugin's settings.

- **Compile vault** (without the dots) still compiles at once with the saved
  settings, without a window.
- **Compile vault from this file** in the file menu opens the same window with
  that note as the starting file.

### Settings in sections, with a reset per section (US-7.4 AC-11, #129, #131)
The settings tab starts with `Vault Compiler 0.25.0` and a **Copy debug info**
button, then four collapsible sections: **Compile**, **Maps** (TextMapper
rendering, with the map font and label tidying behind its gear), **Headings**
and **Entry data**. Each section ends with **Reset this section to
defaults**, behind a question that starts on *Cancel*; it resets that
section's values only.

### Copy debug info (US-7.4 AC-13, #129, #131)
Copies, as plain text: the plugin's and Obsidian's versions, the enabled
plugins with their versions, and the plugin's settings file. Nothing is sent
anywhere.

## Changed behaviour
- **No question before replacing the compiled file** (US-7.4 AC-3, amends
  US-0.3). The document and its `assets/` are the plugin's own output and are
  replaced; the compile window says so beforehand. The browser's
  `confirm` box is gone, and with it the notice *Compilation cancelled.*
- **Values chosen in the window are saved when Compile runs** (US-7.4 AC-4,
  amends US-7.3 AC-3, AC-4). Folder and filename always; the starting file
  when the window was opened from the ribbon or **Compile vault…** (from the
  file menu it is used for that run only). Before, the export prompt saved
  nothing.
- **Notices in the standard's wording** (US-7.4 AC-10): `✅ Compiled
  Exports/compiledtext.md: 12 files, 3 assets, 0 deduplicated.` (with the
  additions for omitted entries and notes not compiled, unchanged) and
  `❌ Compilation failed: <message>`. *Vault compilation started.* is no
  longer shown. Refusals and the map notices keep their texts.
- **Text fields in the settings are saved on Enter or when you leave the
  field** (US-7.4 AC-12, amends US-7.1 AC-S1), not while typing; closing the
  settings or switching the plugin off saves a value still being typed.
- **Browse** is now **Choose folder…**, in the window and the settings.
- Every text of the window, the settings and the notices comes from one
  string table (US-7.4 AC-14); the warnings file's texts are unchanged.

## Breaking changes and migration
- None for the compiled output: the book is byte-identical to 0.24.0's for
  the same vault and settings (US-7.4 AC-6; the fixture by a golden test, a
  323-note book at the manual check: 68 of 68 files with the same SHA-256).
- **Obsidian 1.6.6 or newer** is required (`minAppVersion`, was 1.0.0): the
  new window and settings use API calls that older versions lack. Tested on
  Obsidian 1.15 (desktop).
- If you relied on the overwrite question, check the grey line in the compile
  window before compiling.
