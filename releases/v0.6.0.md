# Release Notes — v0.6.0

**Released:** 2026-10-15

---

## New feature: heading-anchored embeds

### `![[file.md#Heading]]` now embeds only the named section

Previously, an embed that pointed at a heading anchor — such as
`![[About Obsidian#Links are first-class citizens]]` — was treated
identically to `![[About Obsidian]]` and embedded the entire target file.
This did not match Obsidian's own behaviour.

**In v0.6.0**, the compiler extracts only the section that begins at the named
heading and runs until the next heading of equal or greater importance
(lower or equal heading level number), or to the end of the file when
the target is the last heading.

#### What is included

- The named heading line itself.
- All body content directly below it.
- Any subheadings nested beneath it (and their content).
- Content through to the end of the file when no peer/ancestor heading
  follows.

#### What is excluded

- Content that precedes the named heading in the file.
- Sibling headings at the same level and everything after them.
- Any heading of higher importance (lower `#` count) that follows.

#### Auto-heading suppression

Normally, `![[file.md]]` injects a filename-derived heading (`## 2.1 Intro`)
and strips the file's own first heading.  With an anchor, **no auto-heading
is injected**.  The section's heading as written in the source file appears
verbatim in the output.

#### Case-insensitive heading matching

The anchor is compared case-insensitively against heading text.
`![[About Obsidian#links are first-class citizens]]` matches
`## Links Are First-Class Citizens` in the target file.  When multiple
headings normalise to the same text, the first occurrence is used.

#### Missing anchor

When the named heading does not exist in the target file, the compiler emits:

```
<!-- Warning: Missing heading anchor: file.md#HeadingName -->
```

A `WarningDetail` entry is also recorded, attributed to the correct vault
source file (not `'compiled-output'`), with an approximate line number.
No content from the target file is included.

#### Plain embeds are unchanged

`![[file.md]]` (no anchor) continues to behave exactly as before:
full-file embed with filename-derived auto-heading.

## User stories amended

The following user stories were updated to reflect Obsidian's actual
heading-anchored embed behaviour (both were previously unspecified on
this point):

- **US-1.2** — added anchor embed criterion: section boundary, auto-heading
  suppression, missing-anchor warning.
- **US-3.1** — added heading anchor resolution rules: case-insensitive
  matching, missing anchor treated as a missing reference.

## Upgrade notes

No breaking API changes.  Consumers of `CompileResult` that pass embed
anchors (e.g. `![[file#Section]]`) will now receive section-only content
instead of the full file.  If the heading does not exist, a warning
comment is emitted and a `WarningDetail` entry is added; previously the
whole file was silently included.
