# v0.9.0 Release Notes — Pass-Through Embed (US-7.3)

**Date:** 2026-10-16 | **Tests:** 357/357

## What changed

When `normaliseHeadings` is on, a file that contains only a single embed of another file — with no other content besides whitespace — and whose embed target starts with a heading is now treated as a **pass-through wrapper**.

Previously this produced an unwanted double-header:

```
# Wrapper filename       ← injected by US-7.2
## Target's heading      ← target heading shifted one deeper
```

Now the wrapper is transparent and the target's heading surfaces at the wrapper's assigned depth:

```
# Target's heading       ← at the wrapper's depth, no wrapper title
```

## Rules

| Condition | Behaviour |
|---|---|
| Whitespace + single non-anchor embed; target starts with heading | Pass-through: target heading at wrapper's depth |
| Wrapper has own non-whitespace content | No pass-through — wrapper gets preamble title (US-7.2) |
| Wrapper has ≥ 2 embeds | No pass-through |
| Embed has `#anchor` | No pass-through |
| Target is preamble-starting or headingless | No pass-through |
| Wrapper has numeric prefix | Pass-through at prefix depth |
| Recursive chain A → B → C | All links collapse; final file's heading at A's depth |
| `normaliseHeadings: false` | No pass-through detection |
