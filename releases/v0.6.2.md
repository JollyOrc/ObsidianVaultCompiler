# v0.6.2 — URL-encoded heading anchor fix

**Released:** 2026-10-15

## Bug fixed

**Missing heading anchor warning for `%20`-encoded anchors**

When Obsidian generates `![[file.md#Body%20Magic]]` (URL-encoding spaces in heading names), the plugin raised a spurious "Missing heading anchor" warning and produced no output for the section, even though Obsidian itself resolves the link correctly.

**Root cause:** In the `resolve()` method, the `options.resolve` branch (used by the Obsidian plugin at runtime) extracted the anchor fragment from the raw link without calling `decodeURIComponent`. The fallback branch (used in tests and headless compilation) already decoded the full raw string before splitting on `#`, so it was unaffected. The decoded anchor (`Body Magic`) was then compared against actual heading text, while the undecoded anchor (`Body%20Magic`) could never match.

**Fix:** One line — `decodeURIComponent()` applied to the anchor after extraction in the `options.resolve` branch:

```typescript
anchor = decodeURIComponent(split.slice(1).join('#'));
```
