# v0.17.0 Release Notes

**Released:** 2026-10-31

## New features

### Map directives: no hex outlines, no label glow (US-4.10, #92)
A map can now drop the Text Mapper plugin's black hex outlines and the white
glow behind its labels in the compiled PNG, with one comment line in the map:

```text-mapper
# vault-compiler: no-outlines no-glow
skill-moss attributes fill="none" stroke="#4f7d4a" stroke-width="7"
0101 skill-moss "Root Grip"
```

- `no-outlines` removes the outline of every hex; fills, symbols, paths and
  labels stay.
- `no-glow` removes the white glow behind hex labels and path labels; linked
  labels stay links.
- The two words work alone or together, with "Tidy map labels" on or off.
- The line is a comment for the plugin, so the map in Obsidian is unchanged.
  Maps without the line compile as before.
- An unknown word (`no-outline`) is ignored and listed in the compile report
  with its note.
- If the plugin draws a map in a shape the compiler does not know, the
  directive is skipped for that map and a notice says so.

Why a line in the map: the plugin adds its own Gnomeyland definitions after
the map's lines, so a map's own `default attributes`, `glow` and `label`
lines have no effect, and a type named like a built-in one (`red`) is
replaced by it. Give custom types names of their own, and add `option global`
when the map defines SVG filters.

## Bug fixes

### A map without labels is no longer reported as not tidied (#91)
With "Tidy map labels" on, a map without any label showed the notice "some
maps were not tidied (labels)". The empty labels group is written
self-closed (`<g id="labels-…"/>`), which the compiler did not recognise.

## Changed documentation
- US-4.9 no longer claims that a map's own label attributes change the label
  size; only a size on the label itself (`"Moss" 14`) does.
- SCAR-030: a dependency that applies its defaults after the user's input.

## Known issues
