## Changed behaviour

### Code is copied as written (US-1.4, #84, #103)
Anything Obsidian shows as code now reaches the compiled document exactly as
written, and nothing inside it is carried out or reported. Until now:

| In a note | Before | Now |
| --- | --- | --- |
| `` `![[Chapter 1]]` `` (inline code) | the note was pasted between the backticks | kept as written |
| a list of links in a ```` ``` ```` block | the notes were pasted into the block | kept as written |
| `![[A]]` or `![x](pic.png)` in a code block | embedded or copied | kept as written |
| `[[A]]`, `[[Nope]]`, `[x](#Gone)` in code | replaced by warning comments, with warnings | kept as written, no warning |
| a ```` ```dataview ```` example inside a ```` ````md ```` block | deleted | kept as written |

Code means: a block between ```` ``` ```` or `~~~` lines (a ```` ```` ```` block
holds an inner ```` ``` ````), a line indented by four spaces or a tab after an
empty line (inside a list four more than the item's text, so nested tables of
contents are not code), and inline code between backticks, also over several
lines of one paragraph — as measured in Obsidian.

**Migration:** if a book relied on an embed or link inside code being carried
out, take it out of the code.

## Bug fixes

### An unclosed code block ends with its note (US-1.4 AC-6, #102, #103)
A note that opened a code block and never closed it turned the rest of the
compiled book into code. The block is now closed at the end of the note, and
the warnings file names the note and the line of its opening fence.

### Indented code at the start of a note keeps its spaces
With "Normalise headings" off, the first line of a note lost its indentation.
